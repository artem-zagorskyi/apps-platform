# Ревью базы данных

## Контекст проекта

- Postgres 17, Drizzle ORM, миграции drizzle-kit. Партиции создаются SQL-миграциями.
- Эталон схемы — docs/spec.md, раздел 6. Отклонение от него допускается только с записью в docs/adr/.
- Данные сбора не удаляются никогда. Исключение — raw_response старше 7 дней.

### Осознанная денормализация — НЕ считать ошибкой

- `chart_snapshot.app_ids` и `serp_snapshot.app_ids` — массивы `bigint[]`: одна строка вместо 200, ради объёма диска.
- `keyword_score.components` и `keyword_features.features` — `jsonb`.
- `app_text` пишется только при изменении хэша текста, `app_metrics` — по датам.

Всё остальное (справочники, приложения, ключи, отзывы, связи) должно быть нормализовано.

## Чек-лист

### Схема

- У каждой таблицы есть первичный ключ. У снимков — составной естественный ключ с датой.
- Внешние ключи на справочники и сущности. Для данных сбора нет `ON DELETE CASCADE`.
- `NOT NULL` у всех полей, без которых строка бессмысленна. `UNIQUE` на внешних идентификаторах `(store_id, ext_id)`.
- Даты — `date` или `timestamptz` в UTC. Деньги и рейтинги — `numeric`, не `float`.
- `store_id` есть везде, где данные относятся к магазину. Аналитические запросы никогда не смешивают iOS и Google Play.
- Нет полей с именами или ID авторов отзывов.

### Индексы

- Под каждый частый запрос (фильтр + сортировка) есть индекс.
- Есть индексы на внешних ключах, по которым идут JOIN.
- Нет дублирующих и неиспользуемых индексов.

### Миграции

- Только вперёд. Одна миграция — одно смысловое изменение.
- Миграция проходит и на пустой базе, и на базе с данными.
- `NOT NULL` для существующей таблицы добавляется с `DEFAULT` или в два шага.
- Изменения больших таблиц (`app_metrics`, `review`, `raw_response`) — с оценкой времени блокировки.
- Партиции `app_metrics` создаются заранее, минимум на 3 месяца вперёд.

### Запросы

- Только параметризованные запросы или билдер Drizzle. Никакого SQL, склеенного из строк.
- Запись снимков — `INSERT ... ON CONFLICT ... DO UPDATE` (идемпотентность).
- Пакетная вставка вместо цикла по одной строке.
- Нет `SELECT *` при чтении больших таблиц.
- На больших таблицах пагинация курсором, а не `OFFSET`.
- Тяжёлые выборки для UI — через материализованные представления, а не на лету.

## Формат ответа

Список проблем: `файл:строка` — что не так — почему это важно — как исправить. Важность: **критично** / **стоит исправить** / **мелочь**. Если проблем нет, так и написать. Ничего не исправлять без явной просьбы.
