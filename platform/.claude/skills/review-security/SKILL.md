# Ревью безопасности

## Контекст проекта

- Личный сервис на одном VPS Hetzner. Доступ к UI и API — только через Tailscale.
- Наружу открыт только SSH по ключу. Postgres, Redis, API слушают localhost или интерфейс Tailscale.
- Секреты: ключ OpenRouter, токен Telegram-бота, OAuth Apple Ads, пароль базы. Только в `.env`.
- Персональные данные: имена и ID авторов отзывов не хранятся нигде.

## Чек-лист

### Секреты

- Нет секретов в коде, тестах, фикстурах, `docker-compose.yml`, логах и сообщениях об ошибках.
- Каждая новая переменная есть в `.env.example` (без значения) и в Zod-схеме конфига.
- `.env` в `.gitignore`. Секреты не попадают в Docker-образ (`COPY .env` запрещён).

### Сеть и Docker

- В `ports:` нет `0.0.0.0` и нет публикации портов Postgres и Redis. API — только `127.0.0.1` или адрес Tailscale.
- Контейнеры работают не от root (`user:` в compose или `USER` в Dockerfile).
- Базовые образы с закреплённой версией, не `latest`.
- У Redis задан пароль, у Postgres — отдельный пользователь приложения, не `postgres`.

### API и бот

- Каждый вход API проверяется Zod-схемой: параметры пути, query, тело.
- Нет SQL, склеенного из строк ввода. Лимиты на размер страницы и тела запроса.
- Ошибки наружу без стектрейсов и внутренних путей.
- Бот отвечает только chat ID из белого списка в `.env`; остальные сообщения игнорируются без ответа.
- Команды бота не принимают произвольный SQL и не запускают shell.

### Внешние источники

- Ответы магазинов и LLM — недоверенные данные: проходят Zod, не исполняются, не вставляются в SQL и HTML без экранирования.
- Тексты отзывов и описаний в React выводятся как текст, без `dangerouslySetInnerHTML`.
- Промпты LLM не включают секреты и данные авторов.

### Зависимости

- Новые пакеты оправданы, популярны и поддерживаются; версии закреплены в lockfile.
- `pnpm audit` без high и critical, либо причина записана.
- `@mradex77/google-play-scraper` — точная версия.

### Персональные данные

- Маппер отзывов отбрасывает поля автора до записи в базу и до логирования.
- В логах нет текстов отзывов целиком и нет токенов.

## Формат ответа

Список проблем: `файл:строка` — риск — как использовать уязвимость — как исправить. Важность: **критично** / **стоит исправить** / **мелочь**. Если проблем нет, так и написать. Ничего не исправлять без явной просьбы.
